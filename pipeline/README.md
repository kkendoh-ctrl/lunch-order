# Phase 1〜4: WhisperX 文字起こし + PII マスク + Claude 構造化 + Vault 集約

`iCloud Drive/Just Press Record/` を監視し、新規 `.m4a` を:

1. **Phase 1** WhisperX で文字起こし → `音声記憶/_transcripts/YYYY-MM-DD/HH-MM-SS.json`
2. **Phase 4** Claude に送る直前に PII マスク(電話番号・メール・郵便番号・申請番号・カード番号 + ユーザー辞書)
3. **Phase 2** Claude API で構造化 → `音声記憶/録音/YYYY-MM-DD/HH-MM-SS.md`
4. **Phase 3** エンティティ skeleton 生成 + 日次ノート集約 + 一覧再生成

Phase 2〜4 は `ANTHROPIC_API_KEY` が設定されていれば自動で連鎖実行。未設定なら Phase 1 だけで止まる。

## ThinkPad セットアップ(WSL2 Ubuntu 前提)

### 1. システム依存

```bash
sudo apt update
sudo apt install -y python3.11 python3.11-venv ffmpeg
```

### 2. プロジェクト clone

```bash
cd ~
git clone https://github.com/kkendoh-ctrl/lunch-order.git
cd lunch-order/pipeline
```

### 3. Python 仮想環境

```bash
python3.11 -m venv .venv
source .venv/bin/activate
```

### 4. PyTorch (CPU 版)

WhisperX は torch を要求するが、デフォルトでは CUDA 版を引いて来て巨大になる。Intel Arc は CUDA 非対応なので CPU 版を先に入れる。

```bash
pip install torch torchaudio --index-url https://download.pytorch.org/whl/cpu
```

### 5. その他の依存

```bash
pip install -r requirements.txt
```

WhisperX 初回実行時に large-v3 モデル(~3GB)が `~/.cache/huggingface/` にダウンロードされる。

### 6. `.env` を作る

```bash
cp .env.example .env
```

`.env` を編集。Windows ユーザー名 `<user>` を自分のに置き換える(`echo $USER` ではなく Windows 側のユーザー名):

```
JPR_INBOX_PATH=/mnt/c/Users/<user>/iCloud Drive/Just Press Record
VAULT_PATH=/mnt/c/Users/<user>/iCloud Drive/音声記憶
ANTHROPIC_API_KEY=sk-ant-...   # Phase 2 を動かすなら設定
```

iCloud のフォルダ名はロケールによっては `iCloudDrive` (空白なし) になっていることもあるので、`ls /mnt/c/Users/<user>/` で実際に存在するパスを確認。

`ANTHROPIC_API_KEY` 未設定なら Phase 1 (文字起こし) だけ動く。後から API キーを設定して `python main.py batch` を再実行すれば、既存の `_transcripts/*.json` から Phase 2 だけ追加で走らせられる。

### 7. 動作確認

```bash
# 設定値が正しく読めるか確認
python main.py info

# 1ファイルだけ試しに文字起こし(WhisperX 起動の動作確認)
python main.py test "/mnt/c/Users/<user>/iCloud Drive/Just Press Record/2026-05-23/13-39-19.m4a"
```

## 運用コマンド

| コマンド | 説明 |
|---|---|
| `python main.py info` | 設定値と環境を表示。動作前のヘルスチェック |
| `python main.py test <audio>` | 単一ファイルを処理(軽フィルタ + 文字起こし + 構造化 + 集約) |
| `python main.py batch` | 未処理ファイルを全部処理して終了 |
| `python main.py watch` | watchdog で常駐、新規ファイルを順次処理 |
| `python main.py structure <transcript.json>` | 既存 transcript JSON から Phase 2 だけ単体実行(デバッグ用) |
| `python main.py aggregate` | 既存ノートから skeleton/日次/一覧を再生成(Phase 3 単体) |
| `python main.py failed` | 失敗マーカー (`_failed/`) を一覧表示 |
| `python main.py retry [<audio>]` | 失敗マーカーがあるファイルを再実行(引数なしで全件) |

Phase 3 のノートは先頭に `<!-- auto-generated by aggregator.py -->` / `<!-- auto-skeleton -->` マーカーを入れている。skeleton はパイプラインから再上書きされない(空ファイル = ノート無しと同じ扱い)ので、人物/トピック/場所ノートは安心して手で加筆できる。

```json
  "duration_s": 14.2,

  "language": "ja",
  "transcribed_at": "2026-05-23T13:40:00Z",
  "segments": [
```


## トラブルシュート

### `/mnt/c/Users/.../iCloud Drive/` が見つからない

- iCloud for Windows でちゃんと「iCloud Drive を File Explorer に同期」が ON になってるか確認
- WSL2 で `ls "/mnt/c/Users/$(whoami)/"` してフォルダ名を実機で確認
- ロケールによっては `iCloudDrive` (空白なし) のことも

### 「ファイルがダウンロードされてない」エラー

- iCloud のクラウドアイコン付きファイルは実体が無いので読めない
- エクスプローラで該当フォルダを右クリック → 「常にこのデバイスに保持」

### WhisperX の初回ロードが遅い / メモリ不足

- 初回は ~3GB のモデルダウンロードが走る。気長に待つ
- メモリ8GB 切る場合は `WHISPER_MODEL=medium` か `small` に落とす

### `ffmpeg not found`

- `which ffmpeg` で確認。なければ `sudo apt install ffmpeg`

## Phase 2 の中身

- モデル: `claude-opus-4-7`(`.env` の `ANTHROPIC_MODEL` で変更可)
- Adaptive thinking + effort `medium`(`ANTHROPIC_EFFORT` で調整)
- システムプロンプトは Vault の `_プロンプト/claude-structuring.md` を読む
  - 大きいので **prompt caching** を有効化(2回目以降は ~90% 安い)
  - プロンプトを編集すると一度キャッシュが無効化される
- 1録音から複数コンテキストの抽出に対応(電話中に話題が転換した場合など)
- Claude が「雑談・テスト録音」と判断したら `contexts: []` が返り、ノートは空セクションで生成される

## Phase 4 の中身 (PII マスキング)

- `pii.py` が Claude API 送信直前に走る。vault に書く生テキストはマスクしない
  (vault は ローカル前提・OS 暗号化で守る)
- ビルトインの正規表現:
  - メール → `[メール]`
  - クレジットカード様 16 桁 → `[カード番号]`
  - 日本の電話番号 (0XX-XXXX-XXXX 等) → `[電話番号]`
  - 郵便番号 (XXX-XXXX) → `[郵便番号]`
  - 7 桁単独数字 (申請番号) → `[申請番号]`
- ユーザー辞書 (`PII_DICT_PATH` で指定)
  - 形式: `key: replacement` の flat YAML
  - 長いキー優先で substring 置換
  - **Git にコミットしない**。Vault 外で管理(自分の家族名や業者名など)
- `PII_MASK_ENABLED=false` で無効化可
- ログには `masked=N` で置換件数が出る
- spec §4.3.5 の GiNZA/spaCy NER は Phase 5 以降

## Phase 3 の中身

- `aggregator.py` が録音ノートを書いた直後に走る
  - `人物/` `トピック/` `場所/` の skeleton を必要な分だけ作成(既存ファイルは触らない)
  - 当日の `日次/YYYY-MM-DD.md` を再生成(その日の全録音ノートを wikilink で並べ、ToDo と重要録音を集約)
  - `一覧/ToDo.md` `一覧/重要度高.md` を Vault 全スキャンで再生成
- 既存ノートの frontmatter を編集 → `python main.py aggregate` で全部を作り直せる

## Phase 5 の中身

### 5a. 失敗ファイル再実行 (`failure_tracker.py`)

`_process_one` の各段階で例外が起きると `_failed/YYYY-MM-DD/HH-MM-SS.json` に
状況(phase / error / attempt_count / 最終試行日時) を残す。成功すると消える。
`python main.py failed` で一覧、`retry` で再実行。

### 5b. Apple Reminders 連携 (`reminders.py`)

Vault 集約のたびに `<vault>/_reminders/todos.ics` を再生成(RFC 5545 VTODO)。
iCloud Drive 経由で iPhone まで自動で届くので、Files アプリで開いて
「リマインダーに追加」するか、ショートカットで自動取り込みする。
ToDo の UID は録音ステム + index で決定論的 → 再実行で重複しない。
`REMINDERS_ENABLED=false` で停止可。

### 5c. WhisperX 話者分離 (`transcribe.py` の `_maybe_diarize`)

`DIARIZE_ENABLED=true` + `HF_TOKEN=...` で有効化。pyannote.audio のモデル
(~1GB)が初回 DL される。失敗しても致命的ではない(警告を出して原本を返す)。
segments に `speaker` が付き、ノートの全文セクションに `[00:00] {SPEAKER_00} ...`
として表示される。

## 次のフェーズ

- GiNZA NER による未登録人名の自動マスク(`PII_ALLOWLIST_PATH` がここで活きる)
- watch モードの失敗自動リトライ(指数バックオフ)
- 月次まとめ / グラフビューのスナップショット書き出し

詳細は `docs/voice-pipeline.md` 参照。
